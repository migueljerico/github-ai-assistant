### 1. **fix: add PATCH method support to executeAction()**
**SHA:** `61cc79b7`  
**Archivo:** `client/src/services/actionExecutor.ts`

#### Problema
El ejecutor de acciones no soportaba el método HTTP `PATCH`, usado por GitHub para actualizaciones parciales (descripción de repo, visibilidad, permisos). Cualquier intento lanzaba error: `"Método HTTP no soportado: PATCH"`.

#### Solución
Añadido un nuevo case en el switch de métodos:

```typescript
case 'PATCH': {
  const res = await fetch(`https://api.github.com${endpoint}`, {
    method: 'PATCH',
    headers: {
      Authorization: `Bearer ${token}`,
      Accept: 'application/vnd.github+json',
      'Content-Type': 'application/json',
    },
    body: JSON.stringify(action.payload),
  });
  const data = await res.json();
  return { success: res.ok, message: res.ok ? 'Operación completada' : ... , data };
}
```

#### Impacto
- ✅ Habilita actualizaciones parciales de repositorios
- ✅ Mantiene consistencia con POST y PUT
- ✅ Resuelve **issue #4** de MEJORAS_FUTURAS.md

### 2. **refactor: use ref guard in AuthContext to avoid ESLint suppression**
**SHA:** `9c88d4c1`  
**Archivo:** `client/src/context/AuthContext.tsx`

#### Problema
El useEffect que valida el token almacenado usaba un antipatrón: dependencias vacías (`[]`) con `eslint-disable-line react-hooks/exhaustive-deps`. Esto generaba validaciones dobles en Strict Mode y suprimía warnings correctos.

```typescript
// ❌ ANTES
React.useEffect(() => {
  const stored = sessionStorage.getItem('gh_token');
  if (stored && !state.user) {
    fetchUser(stored);
  }
}, []); // eslint-disable-line react-hooks/exhaustive-deps
```

#### Solución
Implementar un ref-based guard para prevenir doble-validación sin suprimir ESLint:

```typescript
// ✅ DESPUÉS
const hasValidated = useRef(false);

React.useEffect(() => {
  if (hasValidated.current) return;
  hasValidated.current = true;

  const stored = sessionStorage.getItem('gh_token');
  if (stored && !state.user) {
    fetchUser(stored);
  }
}, [state.user, fetchUser]); // Dependencias explícitas ✅
```

#### Ventajas
- ✅ Sin suppressions de ESLint
- ✅ Previene doble-validación en Strict Mode
- ✅ Todas las dependencias explícitas
- ✅ Patrón limpio y documentado
- ✅ Resuelve **issue #11** de MEJORAS_FUTURAS.md
